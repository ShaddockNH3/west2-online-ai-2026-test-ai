# 实现说明

12 个函数全部在 `longmen_vs_nabiya.py` 中实现，`python check_my_code.py` 的结果是 11 / 11 全部通过。

## 几点取舍

**`display_status` 的入参校验。** 函数本身只是拼字符串，但最大生命值小于等于 0、
或者当前生命值大于最大值时，说明调用方已经算错了。
这两种情况直接抛 `ValueError`，比默默打印 `HP: 130 / 115` 更容易发现问题。

**`roll_dice` 用 `while` 而不是 `sum()`。** 考核要求用 `while` 练循环，实现上保留了这个形式。数量为 0 或负数时抛异常，因为「掷 0 个骰子」在战斗里没有意义。

**`choose_nagato_action` 的判断顺序。** 先判断自己的血量，再判断对方的血量。如果反过来写，`(29, 19)` 这种双方都危险的情况会返回 `special`，长门就可能带着 29 点血去赌 45% 的概率，测试里专门有一组数据卡这个边界。

**`calculate_final_damage` 与 `apply_damage` 的分层。** 前者只回答「这次打掉多少」，后者负责「扣完之后还剩多少」。拆开之后 `apply_damage` 里的 `max(0, ...)` 只出现一次，也方便单元测试单独验证伤害计算。

**防御值只在对方的下一次行动内有效。** 所以长门攻击或放技能之后要清零娜比娅的防御值，娜比娅行动结束后要清零长门这边的防御值。一开始我忘了清，结果长门的「威仪」在整场战斗里一直生效，娜比娅的伤害长期被吃掉一大半。

## 战斗结果

`python start_the_battle.py` 会带 0.2 秒的停顿逐回合输出。由于伤害全靠骰子，胜负不固定：长门每回合平均掷出 10.5 点，触发 BIG SEVEN（≥ 15）时翻倍，运气好三四回合就能结束，运气差会拖到十几回合。
