# 校园·if 恋

一个纯命令行的攻略游戏：三个决定点，选中一位女主角之后进入她的专属线，
靠聊天和送礼把好感度堆到 100，触发结局。

## 运行

```zsh
cd foundation/foundation1/assignment2-campus-if-love
python main.py
```

需要 Python 3.10 以上（用到了 `X | None` 这种新写法）。

## 目录结构

| 文件 | 职责 |
| --- | --- |
| `main.py` | 入口，只负责创建 `Game` 并启动 |
| `game.py` | 流程：开场 → 三个决定点 → 角色线主循环 → 结局 |
| `character.py` | 角色类：好感度、对话、送礼、结局判定 |
| `story.py` | 数据：对话库、礼物好感度表、场景文案、结局文案 |
| `ui.py` | 终端交互：读取合法选项、打印旁白 |

拆分的思路是「数据和逻辑分开，流程和对象分开」：

- 改剧情只需要动 `story.py`，不用翻逻辑；
- 想换一种交互方式（比如接图形界面），只需要换掉 `ui.py`；
- `game.py` 不该知道好感度怎么加，`character.py` 也不该知道场景怎么切换。

## 玩法

1. 依次经过三个场景，每个场景二选一。选「1」进入对应角色的线，选「2」去下一个场景。
2. 进入角色线后有六个操作：
   - **聊天**：对方抛出一句话，你二选一，答得合心意好感度涨得多，敷衍会掉好感；
   - **送礼**：7 种礼物，每个角色的喜好不同，送错会掉好感（比如给姐姐送夜宵）；
   - **查看好感度**：显示当前数值、距离结局还差多少、聊过几次收过几次礼；
   - **存档 / 读档**：手动存档到 `saves/save.json`，随时读回；
   - **离开**：直接结束游戏。
3. 好感度到 100 触发结局。好感度最低是 0，不会变成负数。

三个人一个都不选的话，游戏会以一句吐槽结束。

## 存档系统（Bonus）

三种存档都在 `game.py` 里实现，数据格式为 JSON：

- **存档**：角色线菜单的「4. 存档」，把当前状态写入 `saves/save.json`；
- **读档**：菜单的「5. 读档」，或者启动游戏时检测到即时存档后按 y 恢复；
- **即时存档**：`saves/autosave.json`，每次聊天、送礼、查看、切换场景之后自动写入，
  永远保存「最近一次操作后」的状态。

快照内容：进度阶段（选人 / 角色线）、已跳过的场景数、当前角色的
好感度、聊天次数、送礼次数。读档时用这些数据**暴力覆盖**当前状态，
对话轮数恢复后，下一次聊天会从存档时的那一句继续。

启动时若检测到 `autosave.json`，会询问「要继续上次的进度吗」，
回答 y 就从上次中断的地方接着玩。存档文件损坏（被改坏 JSON、缺字段）
时会提示错误并当作没有存档处理，不会让游戏崩掉。

## 实现要点

**数据驱动，而不是一堆 `if`。** 对话和礼物都写在 `story.py` 的字典里，
`Character.talk()` 只负责「取第几条对话、把选项打出来、结算 delta」。
加一个新角色只需要在 `DIALOGUES` 和 `GIFT_TABLE` 里补数据，再加一行场景。

**礼物查表带默认值。** 先按角色查，查不到就用 `"*"` 那一档。
「奇怪的石头」只写了 `{"*": -10}`，所以对所有角色都减好感，不用逐个复制。

**对话按次数推进。** `talk_count` 决定用第几条对话；
聊完全部五轮之后重复最后一轮，而不是报错或者从头再来。

**所有函数都带类型注释。** `story.py` 里用 `TypedDict` 描述了 `Dialogue`、`Option`、`Scene` 的结构，
这样编辑器能补全 `dialogue["options"][0]["delta"]` 这种嵌套取值，写错键名会当场报错。

**输入不会把程序弄崩。** `ui.ask_choice()` 负责循环重问，遇到 EOF（`Ctrl + D` 或管道输入用尽）
返回 `None`，由上层当作「退出游戏」处理。
